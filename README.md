## Features Built

### Authentication
- Email and password registration with confirm-password validation
- Email and password login with form validation
- Persistent auth state via Firebase Auth stream
- Logout from home screen
- Automatic redirect: unauthenticated → Login, authenticated → Home

### Alarm Management
- View all alarms in a scrollable list (time, label, enabled/disabled)
- Add new alarm with time picker, label input, repeat days, and snooze config
- Edit existing alarm (tap any alarm tile)
- Delete alarm via swipe or delete button in edit screen
- Toggle alarm on/off inline with a Switch

### Firebase / Cloud Sync
- Every alarm stored under `users/{uid}/alarms/{alarmId}` in Firestore
- Real-time sync via Firestore snapshot stream
- All alarms scoped strictly to the authenticated user

### Local Storage & Offline Support
- All alarms cached locally with Hive
- App fully functional without network (reads from Hive)
- On network restoration, Firestore data is fetched and merged into Hive

### Alarm Notifications
- Local notifications scheduled at the exact alarm time
- One-time or daily repeat based on selected days (Mon–Sun)
- Disabled alarms never schedule a notification
- Snooze support (5 / 10 / 15 / 20 minutes)

### Bonus Features
- Firebase Cloud Messaging (FCM) for push notification delivery
- Dark mode toggle persisted per user in Firestore

## Firebase Setup Steps

### 1. Create Firebase Project
1. Go to [https://console.firebase.google.com](https://console.firebase.google.com)
2. Click **Add project** → name it (e.g. `alarm-clock-app`) → disable Google Analytics → **Create project**

### 2. Enable Authentication
1. In the Firebase console: **Build → Authentication → Get started**
2. Under **Sign-in method**, enable **Email/Password** → Save

### 3. Create Firestore Database
1. **Build → Firestore Database → Create database**
2. Choose **Start in production mode** → select a region → **Enable**
3. Navigate to **Rules** tab and paste:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

4. Click **Publish**

### 4. Enable Cloud Messaging (FCM)
1. **Project settings → Cloud Messaging** — note the **Server key** for any backend triggers

### 5. Connect Flutter to Firebase

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

Select your Firebase project and check **Android** only. This generates:
- `lib/firebase_options.dart`
- `android/app/google-services.json`

## How to Run

### Prerequisites
- Flutter SDK ≥ 3.19.0
- Android Studio / VS Code with Flutter plugin
- Android emulator or physical device (Android 5.0+)
- Java 17+

### Steps

```bash
# 1. Clone the repository
git clone https://github.com/anj2609/clock.git
cd alarm_clock_app

# 2. Install dependencies
flutter pub get

# 3. Generate Hive adapters
flutter pub run build_runner build --delete-conflicting-outputs

# 4. Configure Firebase (see Firebase Setup Steps above)
#    Ensure lib/firebase_options.dart and android/app/google-services.json exist

# 5. Run on Android
flutter run

# 6. Build release APK
flutter build apk --release
# Output: build/app/outputs/flutter-apk/app-release.apk
```

## Architecture Decisions

| Decision | Rationale |
|---|---|
| Riverpod over Provider | Better compile-time safety, no BuildContext dependency in providers |
| GoRouter | Declarative routing with URL-based auth guard redirect |
| Hive over SharedPreferences | Typed object storage; storing full Alarm objects is cleaner than JSON strings |
| Services layer strict isolation | Zero Firebase calls in UI; makes testing and swapping backends trivial |
| Zero code comments | Clean, self-documenting code enforced as a discipline; names convey intent |
